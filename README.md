# claude-task-master 使用教程

> 适合第一次使用的快速上手说明。

## 1. 什么是 claude-task-master

`claude-task-master` 可以理解为「把开发需求拆解并执行」的工作流：

1. 明确问题（需求/缺陷）
2. 探索代码仓库
3. 制定最小改动计划
4. 实施改动并验证
5. 汇报进度并提交结果

---

## 2. 使用前准备

- 有一个可访问的代码仓库
- 能在本地或 CI 环境运行基础命令（如 `git status`、`docker build`）
- 提供清晰的问题描述（越具体越好）

建议在提问时包含：

- 仓库路径
- 问题描述
- 期望结果
- 是否有额外约束（例如“最小改动”“只改文档”等）

---

## 3. 标准使用流程

### 步骤 0：给出任务

示例：

- “请在仓库里补充 claude-task-master 的中文使用教程，并保持最小改动。”

### 步骤 1：先了解仓库

- 查看目录结构和关键文件
- 找到已有的构建/测试方式
- 先运行一次现有检查，确认基线问题

### 步骤 2：先报计划，再改代码

- 先输出 checklist（待办清单）
- 按清单逐步完成，避免一次性大改

### 步骤 3：最小化改动

- 只修改和需求直接相关的文件
- 不顺手修无关问题
- 保持原有风格

### 步骤 4：验证改动

- 运行与改动相关的检查/测试
- 文档改动重点做人工校对

### 步骤 5：阶段性汇报

- 每完成一个有意义的小目标就汇报进度
- 说明已完成项和剩余项

---

## 4. 在本仓库中的一个最小示例

如果需求是“补充 claude-task-master 使用教程”，最小改动通常是：

1. 新增或更新 `README.md`
2. 写清：概念、流程、示例、常见问题
3. 不改 Dockerfile 和工作流逻辑

---

## 5. 常见问题

### Q1：一定要先跑测试吗？

建议先跑仓库已有的构建/测试，先知道当前基线是否健康，再开始改动。

### Q2：没有测试框架怎么办？

如果仓库本身没有测试基础设施，可以不新增测试工具；保持最小改动即可。

### Q3：怎样提高一次通过率？

- 需求写具体
- 限定范围（文件、模块）
- 指定验收标准（例如“文档中文、包含步骤和示例”）

---

## 6. 可复用的提问模板

你可以直接复制下面模板：

```text
请在仓库 <repo> 中完成以下任务：
1) 问题：<problem>
2) 目标：<expected outcome>
3) 约束：最小改动，只修改相关文件
4) 验证：运行仓库已有检查，并说明结果
```

这样通常能得到更稳定、可审查、可落地的结果。
